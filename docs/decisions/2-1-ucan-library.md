## Question

Which capability-token implementation should sit behind the `CapabilityAuth` port
(architecture 4.1), given that verification must be a pure function of its inputs and an
explicit `logTime` (AD-6), all attenuation rules must hold, and the code must bundle for an
Expo app on Android, iOS and web?

## Candidates

1. **`@ucans/ucans` 0.12.0** (ts-ucan), UCAN 0.8.1, Apache-2.0. Last npm publish
   2023-07-25.
2. **`iso-ucan` 2.0.0**, UCAN 1.0 (delegation envelopes in DAG-CBOR, varsig, commands and
   policies), MIT. Last npm publish 2026-10-01.
3. **In-house minimal chain** (prototype only): `did:key` Ed25519 identities; delegation
   tokens as canonical JSON signed with Ed25519 (`@noble/ed25519`, MIT); explicit `logTime`;
   attenuation and caller-supplied revocation implemented directly. No UCAN library.

## Method

- Run the repo's real `CapabilityAuth` contract (`@shopong/ports-contract`, **17 tests**) in
  **3 variants**: normal, `Date.now`/`new Date`/`fetch` trapped during `verify`, and
  issue-time attenuation checks off. 17 x 3 = 51 assertions per candidate.
- The tests are in `spikes/2-1-ucan/test/contract.test.ts`; the counts in
  `results/contract.json` are generated by `pnpm run results` (vitest JSON reporter), not
  typed.
- Measure one minified ESM library bundle per adapter with `vite.build` and gzip -9 in the
  same script. This is a like-for-like library-level measure, not the full app bundle.
- Try the same test suite on Hermes by bundling the Expo probe for Android, iOS and web.
  No device or emulator was available, so this is bundle/compile evidence only.
- Read the library code and tests to separate what the library enforces from what the
  adapter must enforce (`results/owned-logic.md`).

| Run time              | 5,463 ms for all three adapters (emulator on a workstation; not a low-end figure)                    |

**What had to be added to the probe before it would run.** None of these are library bugs.

1. **A `crypto` module stand-in.** `iso-base` runs `import crypto from "crypto"` and then reads
   `crypto.webcrypto`. The probe's Metro config mapped `crypto` to `expo-crypto`, which has no default export,
   so the app died at startup with `Cannot read property 'webcrypto' of undefined`. The probe now maps
   `crypto` to a small module that exports `webcrypto` (the global `crypto` object) as both a named and a
   default export. It was not tested whether ts-ucan or the in-house chain also need it.
2. **`crypto.randomUUID`.** The contract's own `unique()` helper (`packages/ports-contract/src/support.ts`)
   calls `globalThis.crypto.randomUUID()`, which Hermes does not provide. Without it, 16 of 18 cases failed
   on all three adapters with `undefined is not a function`. The polyfill takes `randomUUID` from `expo-crypto`.
   Any on-device run of the contract needs it.
3. **`packages/events` on the Metro watch list.** The in-house adapter imports from it.

With those three changes the polyfill list for Hermes is now: `globalThis.crypto`, `crypto.getRandomValues`
(expo-crypto), `crypto.randomUUID` (expo-crypto), `crypto.subtle.digest` (`@noble/hashes`), plus the Metro
aliases for `crypto`, `stream` and `buffer`.

**What this does not show.**

- It is an x86 emulator on a workstation. It says nothing about a low-end phone's memory, cold start or
  speed.
- iOS and web were not run. iOS needs a Mac or an iPhone. The earlier web evidence is a bundle only.
- The emulator process exited twice during the session with no crash message and was restarted with
  software rendering (`-gpu swiftshader_indirect`). Logcat cuts long lines, so the full result was read from
  the Metro log, not from `adb logcat`.

The probe changes, the result JSON and a screenshot were kept outside the repo, in
`/tmp/ucan-probe-results/` on the machine that ran it. They are not committed.

## Decision

**Go with `iso-ucan` 2.0.0 as the UCAN adapter behind `CapabilityAuth`, conditional on the
Hermes device smoke test.** Keep `@ucans/ucans` out of the implementation path: it is stale
(last publish 2023-07-25), its `verify` cannot accept a log time, and it enforces almost none
of the port's capability semantics. Keep the in-house prototype as spike evidence, not as a
production dependency.

Rationale:

1. **Determinism is the hard constraint.** `iso-ucan` is the only library that takes an
   explicit `now`; ts-ucan forces us to disable its time checks and own the window.
2. **It enforces the most semantics.** Command narrowing, resource globs and ceiling
   monotonicity are handled by its policy engine. We still own the time-subset rule,
   exclusive expiry and the port error mapping, but less security-critical logic than with
   ts-ucan.
3. **It is maintained.** 2.0.0 was published on 2026-10-01; ts-ucan has been untouched since 2023.
4. **The cost is bundle size and mapping code.** iso-ucan is larger and its UCAN 1.0 model
   does not match our resource/ability/ceiling/proof-embedding model, so the adapter maps
   between them. That is contained behind the port.
5. **The in-house option is not ready for production.** It is the smallest and cleanest
   prototype, but it is unaudited, has no external specification or interoperability story,
   and would make us the maintainers of a token format.

The condition: the Hermes smoke test must show all three adapters (or at minimum the chosen
iso-ucan adapter) running on a real low-end Android phone and an iPhone with 17/17 + AD-18
and no missing polyfills. The Android emulator leg passed on 2026-10-25 (18/18 for all three, with the
polyfills listed above). The phone and iPhone legs were not run: on 2026-10-25 the product owner accepted the
decision without them (see Status), so they remain an accepted risk.

## Exit path through the port

`CapabilityAuth` is the only interface the app, the OCN Node and the MCP server use. The
planned adapter package holds the `iso-ucan` implementation; no caller imports `iso-ucan`
directly. If the library breaks, becomes unmaintained or the 3.5x app-level bundle is
unacceptable, the steps are:

1. add a new adapter under the adapters package that implements the same 17-test contract;
2. run the contract in all 3 variants against the new adapter;
3. switch the adapter binding in the composition root only;
4. keep token compatibility only if the record contains already-issued tokens; otherwise
   migrate with a new root grant.

The in-house prototype is a working reference for step 1 if that becomes necessary.

## Risks

| Risk                                                                                             | Likelihood / impact | Mitigation                                                                                  |
| ------------------------------------------------------------------------------------------------ | ------------------- | ------------------------------------------------------------------------------------------- |
| iso-ucan bundle is about 3.5x ts-ucan at app level (1.6x in the tree-shaken library build)       | medium / medium     | measure the release build on the target low-end phone; the port makes replacement contained |
| UCAN 1.0 has no time-subset rule; a child could outlive its parent if we forget `outlivesParent` | medium / high       | contract tests exercise it; adapter checks every link; keep the test in CI                  |
| iso-ucan expiry is inclusive in seconds; the port is exclusive in milliseconds                   | medium / medium     | adapter converts and applies `windowError`; test covers `exp == now`                        |
| Mapping our model onto subject/command/policy is lossy or subtle                                 | medium / high       | contract suite is the guard; no library objects cross the port boundary                     |
| Device/Hermes behaviour differs from Node (crypto, Buffer, parse time)                           | medium / high       | run the smoke test on real Android and iPhone; keep polyfills explicit and reported         |
| ts-ucan remains tempting as a smaller dependency                                                 | low / high          | this decision + R-2; do not import it outside the spike                                     |
| In-house prototype mistaken for production code                                                  | low / high          | lives only under `spikes/2-1-ucan/`, marked prototype, not in the workspace                 |
